Шлюз для устройств сети…

    
Устройства в сети указывают IP этого сервера как шлюз, и их трафик идёт через sing-box (TUN). Включается только кнопкой. Если sing-box нужен только на этом устройстве — ничего здесь включать не нужно: TUN и так обслуживает только саму машину. Выключение удаляет правила iptables и возвращает настройки ядра, какими они были до включения.

    

      
      
      
    

    

      
      
    

    

    
Что делает: ip_forward=1, send_redirects=0, rp_filter=2 (loose); NAT только для трафика, уходящего мимо TUN; разрешение FORWARD для подсети (нужно, если Docker включил политику DROP); TCP MSS clamp. Правила применяются отдельной службой и переживают перезагрузку. Только IPv4.

  


  

    
DNS в sing-box (для шлюза и TUN)…

    
Если у клиентов шлюза не открываются сайты по именам, включите это. sing-box начнёт сам отвечать на все DNS-запросы, которые через него проходят, и (если порт 53 свободен) на самом устройстве: российские домены (.ru, .su, .рф) через 77.88.8.8 напрямую, остальные — через DoH 1.1.1.1 по вашему основному маршруту. В конфиг добавятся секция dns и правила hijack-dns; выключается кнопкой обратно. Нужен sing-box 1.11+.

    

  


  

    
Прокси-сервер (SOCKS5 и HTTP) в sing-box…

    
SOCKS5 и HTTP-прокси встроены в sing-box: трафик не проходит лишний путь «контейнер → Docker-сеть → TUN», поэтому нужно меньше процессора и скорость выше. Порты по умолчанию 1080 (SOCKS5) и 1081 (HTTP). Работает по правилам маршрутизации. Без логина: открыто всей локальной сети.

    

  


  

    
Доступ к веб-интерфейсу панели…

    

      

    

    
Без галочки панель слушает только 127.0.0.1: открыть её можно с самого сервера или через SSH-туннель ssh -L 8088:127.0.0.1:8088 user@сервер. Вернуть доступ из консоли: sudo singbox-panel lan on.

  







  

    Нужен Clash API
    
Через него панель переключает сервер на лету, без перезапуска sing-box. Будет добавлен experimental.clash_api (только 127.0.0.1) и cache_file, чтобы выбор сохранялся после перезапуска.

    
  

  

    Выбранный сервер не сохранится после перезапуска: в конфиге выключен cache_file.

Работает, пока запущена служба панели (singbox-panel). Включается только кнопкой.

Операционная система

    
Обновление пакетов системы через apt — только по вашим кнопкам. Конфиги сервисов не перезаписываются (остаются ваши версии). Обновление идёт отдельной фоновой задачей и не прервётся, даже если панель перезапустится.

    

    

      
      
      
    

    

    

    

  







  
  

  
С чего начать
    
    
      
  1. Подписка. Вкладка «Подписка» → «+ Добавить подписку», вставьте ссылку, оставьте группу proxy, нажмите «Обновить все и применить». В группе появятся серверы.
    2. 
      
  2. TUN. Если на главной написано «TUN не настроен», нажмите «Включить TUN»: весь трафик устройства пойдёт через sing-box. Без TUN через него идёт только трафик, отправленный на его прокси-порты.
    3. 
      
  3. Маршрут по умолчанию. «Серверы» → у группы proxy нажмите «Направить весь трафик сюда» (то же самое: «Маршрутизация» → «Остальной трафик (final)» = proxy).
    4. 
      
  4. Выбор сервера. На главной или на вкладке «Серверы» выберите узел в группе. Переключение происходит сразу, без перезапуска.
    5. 
    

    
Если sing-box ещё не установлен, при первом входе откроется «Быстрый старт»: он поставит sing-box и сделает эти шаги за вас. Он показывается один раз, его можно пропустить.

    
Резервный сервер: «Серверы» → «Резервный сервер». Выберите группу, основной и резервный серверы. Панель проверяет основной каждые 30 секунд и после нескольких неудач подряд переключает группу на резерв, а потом возвращает обратно. Работает, пока запущена панель.

    
Нужно, чтобы sing-box работал только на этом устройстве? Режим шлюза и DNS для сети не включайте, достаточно TUN. Встроенный прокси при включении можно ограничить адресом 127.0.0.1. Вернуть всё к исходному состоянию можно кнопкой «Настройки → Сервер → Удалить всё».

    
Всё остальное (шлюз, DNS, прокси, наборы маршрутов) включается отдельными кнопками и ничего не делает само.

  


  
Главная
    
    
      
  • Подключён к серверу — выбранный узел и цепочка до него (группа → узел). Здесь же можно сменить сервер.
    • 
      
  • Если трафик идёт мимо выбранной группы, под списком появится предупреждение с кнопкой «Направить весь трафик через …».
    • 
      
  • Графики показывают весь трафик sing-box (если включён Clash API), иначе только интерфейс TUN. Счётчики обнуляются при перезапуске службы.
    • 
      
  • Подписка — срок действия и остаток трафика, если сервер подписки их сообщает. Данные обновляются при обновлении подписки и раз в 6 часов, кнопка «↻ Обновить» спрашивает сразу.
    • 
      
  • За всё время — трафик по всем сессиям sing-box, переживает перезапуски. Считает панель, обнулить можно ссылкой «обнулить».
    • 
      
  • Масштаб графиков — окно от 1 минуты до часа (выпадающий список или колесо мыши над графиком), шкала скорости обычная или логарифмическая. История копится, пока страница открыта.
    • 
      
  • Нагрузка устройства — CPU, память, swap, температура.
    • 
      
  • Кнопки «Перезапустить» и «Остановить» управляют службой sing-box, не самой панелью.
    • 
    

  


  
Серверы
    
    
      
  • Показаны группы selector и urltest. В selector узел выбираете вы, urltest выбирает сам по задержке. Чтобы выбирать вручную, нажмите «Сделать selector».
    • 
      
  • «Проверить задержки» — тест всех узлов группы, ⏱ у узла — тест одного. Значок ● отмечает текущий узел.
    • 
      
  • «Разрывать текущие соединения при смене» закрывает открытые соединения, чтобы новый сервер заработал сразу.
    • 
      
  • Метка «не используется» значит, что ни final, ни правила не ведут в эту группу, выбор в ней ни на что не влияет.
    • 
      
  • Для переключения нужен Clash API. Если его нет, панель предложит включить (только 127.0.0.1) и сохранить выбор после перезапуска.
    • 
    

  


  
Подписки
    
    
      
  • Можно добавить несколько подписок. У каждой свой префикс узлов, поэтому они не мешают друг другу.
    • 
      
  • Группы — куда добавлять узлы (по умолчанию proxy). Если группы нет, она создаётся.
    • 
      
  • Автообновление — интервал в часах, 0 — выключено.
    • 
      
  • Заменить одноимённые узлы — если такие же узлы были добавлены вручную, они заменятся узлами подписки, а ссылки на них в группах и правилах перепишутся.
    • 
      
  • User-Agent — нужен, если сервер подписки отвечает «не найдено». По умолчанию панель пробует несколько подряд.
    • 
      
  • Ключи без подписки — «+ Добавить ключ (vless://…)»: вставьте одну или несколько ссылок vless://, vmess://, trojan://, ss://, hysteria2://, по одной на строку. Они работают как подписка без адреса: попадают в выбранные группы, «Применить» обновляет узлы.
    • 
      
  • Узлы, которые не принимает ваша версия sing-box, отклоняются с указанием причины и в конфиг не попадают.
    • 
    

  


  
Маршрутизация
    
    
      
  • Правила проверяются сверху вниз, срабатывает первое совпавшее. Всё, что не совпало, идёт по final.
    • 
      
  • Добавить правило: выберите тип условия (домен с поддоменами, точный домен, подсеть, порт и т. д.), значения через запятую и направление: группа, конкретный сервер, direct или блокировка.
    • 
      
  • Готовые наборы (YouTube, Telegram, ChatGPT/Claude, Discord, Meta, X, Netflix, Spotify, локальные адреса, российские домены): выберите набор и направление, нажмите «Добавить набор». Сами они не включаются. Повторное добавление меняет направление и не создаёт дубликаты.
    • 
      
  • BitTorrent напрямую — галочка записывает правило сразу и перезапускает службу. Определяется по содержимому трафика, зашифрованный BitTorrent может не распознаться.
    • 
      
  • Изменения в таблице — это черновик. Они попадают в конфиг только после «Сохранить и применить» (с перезапуском) или «Сохранить без перезапуска».
    • 
      
  • Если конфиг не пройдёт sing-box check или служба не запустится, прежний конфиг вернётся автоматически.
    • 
    

  


  
Сеть: шлюз, DNS, прокси
    
Режим шлюза

    
Устройство раздаёт интернет другим через sing-box. Включите, выберите интерфейсы (локальный и внешний) и на нужных устройствах укажите шлюзом адрес этого устройства. При включении меняются настройки ядра (ip_forward и др.) и добавляются правила iptables. «Выключить» возвращает всё как было.

    
DNS в sing-box

    
Если у клиентов шлюза не открываются сайты по именам — включите. sing-box перехватывает DNS-запросы, российские домены резолвит напрямую, остальные через DoH. Если порт 53 свободен, клиенты могут указать DNS-сервером адрес устройства. Нужен sing-box 1.11+. Если в конфиге уже есть своя секция dns, панель её не трогает.

    
Прокси в sing-box

    
SOCKS5 (по умолчанию 1080) и HTTP (1081) прямо в sing-box, для устройств, которые не умеют работать через шлюз. Трафик идёт по вашим правилам маршрутизации. Логина и пароля нет: порты открыты всей локальной сети. Для доступа только с самого сервера отметьте «только с самого сервера».

    
Доступ к панели

    
Галочку «разрешить вход из локальной сети» можно снять — тогда панель слушает только 127.0.0.1 и открывается через SSH-туннель. Вернуть доступ с консоли: sudo singbox-panel lan on.

  


  
Обновление sing-box
    
    
      
  • Выберите версию, нажмите «Скачать и проверить»: панель скачивает релиз с GitHub, сверяет контрольную сумму и проверяет ваш конфиг новой версией.
    • 
      
  • Если новая версия не принимает ваш конфиг, установка блокируется. Если конфига ещё нет, проверять нечего.
    • 
      
  • Если sing-box не установлен, панель поставит бинарник в /usr/local/bin/sing-box, создаст службу sing-box.service и минимальный конфиг.
    • 
      
  • Перед заменой сохраняются копии бинарника и конфига (последние 5), «Откатить» возвращает старую версию.
    • 
      
  • Если служба не запустилась после обновления, прежняя версия возвращается сама.

Обновление системы
    
    
      
  • «Настройки → Обновления → Операционная система». Работает на Debian/Ubuntu (apt).
    • 
      
  • «Проверить обновления» скачивает свежие списки пакетов (apt-get update) и показывает, что можно обновить; обновления безопасности помечены. Сама по себе проверка ничего не ставит.
    • 
      
  • «Обновить систему» запускает apt-get upgrade отдельной фоновой задачей: прогресс и журнал видны на этой же карточке, обновление не прервётся, даже если панель перезапустится. Конфиги сервисов остаются вашими.
    • 
      
  • Галочка «full-upgrade» разрешает ставить новые и удалять мешающие пакеты, если этого требуют зависимости.
    • 
      
  • Если после обновления системе нужна перезагрузка (например, обновилось ядро), появится кнопка «Перезагрузить устройство».
    • 
    

  


  
Конфиг
    
    
      
  • «Проверить» — только проверка, «Сохранить» — запись без перезапуска, «Сохранить и перезапустить» — запись и применение.
    • 
      
  • Перед каждым сохранением делается резервная копия, из списка «Бэкапы» её можно восстановить.
    • 
      
  • Блок «Совместимость» показывает устаревшие или недоступные в вашей версии поля.
    • 
      
  • Комментарии в JSON панель не поддерживает.
    • 
    

  


  
Настройки сервера, ограничения, проверка окружения
    
    
      
  • Ограничения CPU и памяти службы sing-box задаются через systemd. Слишком жёсткий лимит CPU режет скорость — при проблемах со скоростью сбросьте его.
    • 
      
  • Проверка окружения показывает, найден ли бинарник, служба и конфиг, достаточно ли прав, тот ли файл читает служба. К каждой проблеме есть подсказка.
    • 
    

  


  
Обновление панели
    
    
      
  • Раз в 2 часа панель проверяет, вышла ли новая версия. Только проверяет: скачивание и установка только по вашей кнопке.
    • 
      
  • В блоке «Что нового» перечислены изменения всех версий, которые новее вашей.
    • 
      
  • Файл проверяется по sha256 и по заголовку пакета, ставится через dpkg. Панель перезапустится на несколько секунд, sing-box при этом не затрагивается.
    • 
      
  • Три последние версии хранятся — можно вернуться кнопкой «Установить эту версию».
    • 
      
  • Если панель установлена не deb-пакетом, автоматическое обновление недоступно.
    • 
    

  


  
Частые проблемы
    
    
      
  • Выбираю сервер, а трафик идёт напрямую. Скорее всего, final указывает на direct. «Серверы» → «Направить весь трафик сюда» у группы proxy.
    • 
      
  • «TUN не настроен» / интерфейс не найден. В конфиге нет TUN-входа. Нажмите «Включить TUN» на главной.
    • 
      
  • Клиенты шлюза не открывают сайты по именам. «Сеть» → «DNS в sing-box» → «Включить».
    • 
      
  • Скорость ниже ожидаемой. Посмотрите график «CPU sing-box». Если одно ядро на 100% — упирается процессор: попробуйте "stack": "system" или "auto_redirect": true в TUN-входе. Проверьте лимиты CPU в «Настройки → Сервер». Для устройств с прокси используйте встроенный прокси в sing-box.
    • 
      
  • Правка не применилась. Таблица маршрутизации — черновик: нажмите «Сохранить и применить». Если служба не стартовала с новым конфигом, он откатывается — причина показана в уведомлении.
    • 
      
  • Подписка отвечает «не найдено». Укажите User-Agent вручную в настройках подписки.
    • 
      
  • Страница ведёт себя странно после обновления. Нажмите Ctrl+F5. Если внизу красный баннер о разных версиях, выполните sudo systemctl restart singbox-panel.
    • 
      
  • Службу не удаётся запустить. «Логи» покажут причину. Если конфиг испорчен, восстановите его из «Настройки → Конфиг → Бэкапы».
    • 
    

  


  
Команды в консоли
    
    
      
  • sudo singbox-panel lan on|off|status — доступ к панели из локальной сети.
    • 
      
  • sudo singbox-panel p2p on|off|status — правило «BitTorrent напрямую».
    • 
      
  • sudo singbox-panel gateway off — выключить режим шлюза и вернуть настройки.
    • 
      
  • sudo systemctl restart singbox-panel — перезапустить панель.
    • 
      
  • journalctl -u singbox-panel -n 50 --no-pager — журнал панели.
    • 
      
  • journalctl -u sing-box -n 50 --no-pager — журнал sing-box.
    • 
    

  


  
Безопасность
    
    
      
  • Панель работает от root, вход по системным учёткам (PAM). Root разрешён всегда, остальные должны быть в группе sudo.
    • 
      
  • Рассчитана на доверенную локальную сеть. В интернет её открывать не стоит. Для удалённого доступа используйте SSH-туннель.
    • 
      
  • Прокси-порты (1080/1081) без пароля: используйте их только в доверенной сети.
    • 
    

  

  
Что-то не получилось? Загляните в «Логи» и «Настройки → Сервер → Проверка окружения».

Быстрый старт

  
sing-box в системе не найден. Мастер поставит его и поможет с базовой настройкой. Если на устройстве остался конфиг прежнего sing-box, он будет переименован (не удалён), а вместо него создан новый. Всё можно пропустить и настроить вручную. Если закрыть окно крестиком или Esc, оно появится снова при следующем входе; кнопка «Больше не показывать» убирает его насовсем.
